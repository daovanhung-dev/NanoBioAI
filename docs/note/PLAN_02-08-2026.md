
### 2.3. Meal generation hiện tại

```text
GeneratedPlanService
-> AIService.generateMealPlanWithSource
-> MealPlanPrompt chỉ gửi allowed codes

-> hydrate tên, mô tả, dinh dưỡng, cách nấu từ SQLite meal_catalog
-> generate exercise
-> LifestyleScheduleTimelineBuilder
-> requestStore.commitGeneratedPlan (transaction/ledger)
-> NotificationBootstrap.scheduleGeneratedReminders
```

Điểm còn thiếu:

- Candidate pool chưa lọc theo hồ sơ dinh dưỡng có cấu trúc.
- Catalog chưa chứa cấu trúc nguyên liệu/bước/công dụng/provenance của 163 công thức.
- Chưa có remote catalog refresh từ Supabase.
- `meal_plans` chưa lưu đủ snapshot/provenance.
- Chưa có đổi món.

### 2.4. Meal/timeline/notification hiện tại

- `lifestyle_schedule_items.source_type = mealPlan`.

- Reminder lấy nội dung từ schedule item và refresh toàn bộ reminder của active subject.
- Vì vậy đổi món phải cập nhật cùng lúc meal snapshot và schedule item; sau commit mới refresh OS notifications.

### 2.5. AI Chat và Nabi hiện tại

### 4.3. UX form đề xuất

Một editor 5 nhóm, có thể mở từ onboarding/profile/nutrition:

1. **Cơ thể & nhịp sống** — body, sleep, activity, water.
2. **Ăn uống & hạn chế** — allergies/intolerance/dislike/food rules.
3. **Sức khỏe đang theo dõi** — symptoms, medications, optional labs.
4. **Mục tiêu** — tối đa 3 mục tiêu có priority/horizon.
5. **Bữa ăn phù hợp** — meal count/times/portion/preparation preferences.
6. **Review ngắn** — chỉ summary, không lặp toàn bộ form.

Progressive disclosure:

- Chọn “Có” mới mở details.
- Labs/medications có repeatable rows và cho bỏ qua.
- Copy không dùng ngôn ngữ chẩn đoán.
- Autosave draft chỉ local; final save transaction.

## 5. Mapping 163 công thức sang catalog

### 5.1. Dữ liệu nguồn xác minh được

- 11 chương nội dung.
- 64 chủ đề sức khỏe.
- 163 công thức.
- Mỗi công thức có: chương, topic, tên, trang PDF, danh sách nguyên liệu, danh sách bước, “Công dụng”.
- Tài liệu yêu cầu giữ nguyên các bất nhất; không tự sửa số chương, số món hoặc nội dung công dụng.

### 5.2. Mapping catalog

| Nguồn | Cột/contract đích | Quy tắc |
|---|---|---|
| Chương | `source_chapter_code`, `source_chapter_name` | Giữ nguyên tên/số từ tài liệu |
| Topic | `health_topic_code`, `health_topic_name`, `health_topic_description` | Code deterministic từ chapter/topic; text nguyên văn |
| Tên món | `meal_name` | Giữ nguyên nội dung; normalize chỉ cho search, không thay display text |
| Số thứ tự trong topic | `source_recipe_order` | Giữ nguyên kể cả bất nhất |
| Trang PDF | `source_page` | Integer nullable, provenance |
| Nguyên liệu | `ingredients_json` | JSON array v1: `{order, text}`; không parser newline ở UI |
| Cách làm | `cooking_steps_json` | JSON array v1: `{order, text}` |
| Công dụng | `benefits` | Text nguyên văn; UI ghi “Theo tài liệu tham khảo”, không biến thành chỉ định |
| Nguồn | `source_name`, `source_version`, `content_hash` | Traceability/import idempotency |
| Loại bữa | `meal_type` | **Không có trong nguồn**; cần metadata được duyệt trước khi AI dùng |
| Khẩu phần | `serving_size` | **Không có nhất quán trong nguồn**; nullable |
| Calories/macros/fiber/water | nullable + `nutrition_status` | Không tự tạo số; chỉ dùng khi verified |
| Allergen/condition tags | structured JSON + `constraint_metadata_status` | Không suy từ “Công dụng”; chỉ dùng metadata được duyệt |
| Active/plan eligibility | `is_active`, `is_plan_eligible` | Content có thể active để xem; AI chỉ dùng record đủ metadata |
| Version | `catalog_version`, `content_version` | Phục vụ cache/disable/rollback |

### 5.3. Import strategy

```text
Markdown source
-> deterministic parser tool
-> canonical JSON artifact
-> validation: 163 records, 64 topics, unique code, non-empty ingredients/steps/benefits/page
-> SQLite seed
-> Supabase seed/upsert
-> content hash/provenance report
```

Không hard-code 163 records trực tiếp trong Dart. Tạo artifact dữ liệu versioned và generator/validator có thể chạy lại.

### 5.4. Metadata gate bắt buộc

Nguồn công thức không cung cấp đủ `meal_type`, nutrition facts, allergen tags và condition constraints. Do đó:

- Import toàn bộ nội dung gốc để hiển thị/search.
- Chỉ record có `metadata_status = approved` và `is_plan_eligible = true` mới vào candidate pool AI/đổi món.
- Existing curated catalog vẫn hoạt động và được migrate sang metadata status approved.
- Không dùng AI runtime để tự gắn nhãn y tế.

## 6. Kiến trúc mục tiêu

### 6.1. Font scale

```text
Onboarding entry/direct onboarding guard
-> SettingsPreferencesController
-> SettingsLocalDatasource / SharedPreferences
-> appTextScaleProvider
```

- Có cờ `textScaleConfigured` để chỉ bắt buộc lần đầu.
- Kết hợp với system text scale theo policy có clamp; không ghi đè accessibility system thành một hằng số.
- Không nhân `fontSize` thủ công ở từng widget.

### 6.2. Nutrition profile

```text
NutritionProfileEditorPage
-> NutritionProfileController
-> NutritionProfileRepository
-> NutritionProfileLocalDatasource
-> SQLite transaction (8 tables)
-> outbox marker
-> immediate sync request nếu authenticated
-> invalidate profile/dashboard/nutrition/meal candidate providers
```

### 6.3. Catalog refresh

```text
App/session catalog refresh
-> MealCatalogRepository
   -> SupabaseMealCatalogRemoteDatasource (active/versioned, read-only)
   -> MealCatalogLocalDatasource/DAO
-> atomic cache replace/upsert
-> retain last-good catalog on network/schema failure
```

- Guest initial plan luôn có bundled/local last-good seed.
- Cloud refresh không làm trống catalog nếu request lỗi.
- Catalog không tham gia user outbox vì là server-owned read-only data.

### 6.4. AI candidate selection

```text
GeneratedPlanService
-> load profile constraints + active plan-eligible catalog
-> MealCandidateSelector
   -> meal type
   -> allergies/restrictions
   -> approved condition tags
   -> verified nutrition/energy window when available
   -> diversity/current plan usage
   -> bounded candidate pool
-> prompt sends minimal metadata
-> AI returns codes only
-> validator enforces candidate membership
-> hydrate immutable snapshot
-> deterministic fallback from same filtered pool
-> commit full plan atomically
```

### 6.5. Meal detail/replacement

```text
MealPlanPage compact card
-> MealRecipeDetailSheet/Page
-> MealPlanController.loadReplacementCandidates
-> MealPlanRepository
-> MealReplacementPolicy + datasource transaction
   -> preserve meal_plan.id
   -> replace snapshot fields
   -> update linked lifestyle_schedule_item by source_id
-> after DB commit: refresh reminders
-> invalidate meal/schedule/dashboard/nutrition providers
```

Giữ nguyên `meal_plan.id` là lựa chọn an toàn nhất để timeline `source_id` và notification identity không bị orphan.

### 6.6. Voice AI

```text
AiVoicePage
-> AiVoiceController (state machine + operation token)
-> SpeechRecognitionGateway
-> AIChatRepository (same quota/error policy)
-> TextToSpeechGateway
-> NabiContext/NabiVisualState
```

State machine:

```text
initializing -> greeting -> idle
idle -> listening -> transcribing -> thinking -> speaking -> idle
any active -> stop/cancel -> idle
permission denied -> permissionDenied
recoverable failure -> error -> idle/retry
route dispose/background -> stop STT + stop TTS + invalidate operation token
```

- Greeting constant phát đúng một lần cho mỗi route instance.
- Greeting không gọi AI và không trừ quota.
- Voice question dùng quota AI Chat hiện tại.
- Người dùng nhấn mic khi Nabi đang nói: stop TTS trước, rồi start listening.
- Không lưu audio.

## 12. Rủi ro và rollback

| Rủi ro | Mức | Kiểm soát | Rollback |
|---|---|---|---|
| Context/task ghi 8 bước nhưng source 9 | Cao | Khóa source làm chuẩn; test step order | Revert docs/UI gate, không migrate onboarding data |
| Catalog nguồn thiếu meal type/nutrition/tags | Blocker nghiệp vụ | Metadata gate; không đưa unapproved records vào AI | Disable `is_plan_eligible`; existing catalog tiếp tục chạy |
| V17 rebuild catalog làm mất dữ liệu | Cao | Transaction, copy-count/hash tests, backup test DB | Restore old table trong migration test/release rollback |
| New profile tables lệch local/cloud | Cao | Contract maps + SQL allowlist tests | Disable cloud sync tables, giữ local rows/outbox pending |
| Meal replacement lệch timeline | Cao | One DB transaction, stable meal ID, source-id test | Transaction rollback; no mutation if any DB write fails |
| OS notification refresh thất bại sau DB commit | Vừa | Durable status, full refresh retry, startup/lifecycle refresh | Keep changed meal; retry reminder; no reverse DB mutation automatically |
| Large text causes overflow | Cao UX | clamp, narrow-screen widget tests, audit touched screens | Reset preset to standard, feature flag/gate rollback |
| Voice permission/native build issues | Cao | gateway abstraction, permission tests, APK/device smoke | Hide voice route/CTA behind capability flag |
| TTS/STT overlapping/stale AI response | Cao | operation token, stop-before-start, lifecycle observer | Controller cancel/reset |
| Supabase anon catalog exposure | Vừa | safe projection, active only, no write, RLS tests | Revoke anon select; use bundled guest cache |
| Medical claims displayed as advice | Cao | provenance label, neutral copy, no generated claims | Hide benefits section while preserving data |
| Token growth from candidate list | Vừa | bounded pool per meal type, minimal fields | Lower pool size, deterministic local selection |

### Rollback strategy theo lớp

- **UI/font/voice:** route/capability flag để tắt mà không rollback DB.
- **Catalog:** versioned rows + `is_active/is_plan_eligible`; rollback bằng version activation, không delete.
- **Nutrition:** additive V17 schema; rollback app vẫn không được downgrade DB destructive. Old app compatibility phải được đánh giá trước release.
- **Supabase:** migration có down/disable notes; revoke policy/RPC, giữ rows để tránh mất dữ liệu.

| Q5 | Giọng TTS cụ thể? | Dùng Vietnamese voice mặc định của thiết bị, tốc độ trung bình, có mute/replay; không khóa vendor/voice ID. |
| Q6 | Có thu thập emergency contact và DOB đầy đủ không? | DOB optional trong nutrition profile; emergency contact không thu thập ở MVP do data minimization. |
| Q7 | Các phần đánh giá chuyên gia, supplement dosage, chữ ký, tái đánh giá có thuộc app user flow không? | Không. Để ngoài MVP cho đến khi có BD/DD và trusted practitioner role. |
| Q8 | “Công dụng” có hiển thị nguyên văn không? | Có, kèm provenance và disclaimer “theo tài liệu tham khảo”; không dùng làm personalized medical decision. |

**Khi người dùng xác nhận plan mà không sửa các Q1–Q8, các default trên được xem là quyết định thực thi.**
