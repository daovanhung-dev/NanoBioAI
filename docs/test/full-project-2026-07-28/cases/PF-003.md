# PF-003 — Guest additional-journey escalation

## Scope

- Persona: `GST-ANON`, the local Guest continuation created in PF-002
- BD / AC / BR: Product Flow M02 and M05; AC-02
- Device/build: physical Android 11 (API 30), `220333QPG`, `com.example.nano_app`, unified `lib/main.dart`, source revision `9e81b08b9ae2aab4e1c263f99b044002059b4bb0` with a pre-existing dirty worktree
- Reset: no reset between PF-002 and PF-003; no second plan, AI request, account action, or server mutation was initiated.

## Preconditions and steps

1. Use the Guest state after its first seven-day journey was created in PF-002.
2. On the Dashboard, attempt the displayed renewal/create-more surface and its chevron.
3. Observe navigation and any login escalation.

## Expected and actual

- Expected: after its one Guest creation has been used, a Guest asking to create another journey must be led to login and must not create another AI journey (AC-02). The BD explicitly says not to satisfy this rule merely by hiding the action.
- Actual: the Dashboard reported that seven days remain and visually locked the renewal control. Both the surface and chevron were non-actionable on-device; no login gate opened and no route change occurred. The user therefore has no path to make the request that AC-02 requires to be escalated.
- Result: FAIL. The failure is a business/UX deviation, not an AI-generation failure.
